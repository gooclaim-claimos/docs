Send three kinds of file — **members**, **claims** and **claim documents** — and, if your
system records them, a fourth: **claim deductions**. Send them by SFTP, or upload them in
Portal under **Data & Connectors → Connectors → Batch Dump**.

## On your SFTP server

Gooclaim OS looks in these folders under the base path you give us:

```text
{base path}/
├── members/
├── claims/
├── claim_documents/
└── claim_deductions/     (optional)
```

- **Every hour**, Gooclaim OS checks each folder for files.
- It takes every file directly in the folder (not in subfolders), whatever its name, **if the
  file was modified in the last 2 hours**. A file copied with an old preserved timestamp is
  not picked up.
- Files whose name starts with a dot are skipped. Upload as `.name.csv` and rename when the
  upload is complete, so a half-written file is never read.
- Gooclaim OS only reads: your files are never moved, changed or deleted.
- Before the first read you approve your server's identity in Portal — see
  [server identity](#server-identity).

## File format

| | By SFTP | Uploaded in Portal |
|---|---|---|
| Formats | CSV | CSV or Excel (`.xlsx`) |
| Encoding | UTF-8 (a byte-order mark is fine) | — |
| Header row | Required | Required |
| Limit | 20,000 rows per file | 20,000 rows, 25 MB |

For Excel files: only the first sheet is read (another sheet with data rejects the file),
merged cells are refused, and very long numbers shown in scientific notation are excluded
from the row.

## What happens to a file

- **The same file twice is processed once.** A file is recognised by its exact contents; if
  the contents change, it is processed again.
- **An older record never overwrites a newer one.** Each row carries the time it was last
  changed on your side; a row no newer than what is stored is skipped.
- **A bad row does not stop the file.** It is set aside with its row number, the field and
  the reason (never the value), and the other rows go in.
- **A whole file is rejected** if it is not valid UTF-8, has no header row, is over the row
  limit, or has no active field mapping yet. Portal shows why.
- Members whose cover ended more than 90 days ago are not stored.

Portal shows each file's result: Synced, Mapped nothing to store, Rejected, Store failed or
Processing failed.

## Claim deductions file

Why a claim was paid less than claimed. One row per deduction. Optional: send it if your
system records deductions.

| Field | Required | Notes |
|-------|----------|-------|
| Claim number | Yes | The claim must already be in a claims file |
| Reason code | Yes | Your own code, e.g. `ROOM_RENT_CAP` |
| Reason wording | No | Shown to the member exactly as you wrote it |
| Amount | No | In rupees or paise; never negative |
| Last changed | Yes | |

- A claim's rows **replace** its earlier deductions as a whole: send every deduction for a
  claim together, in one file. A deduction you drop is no longer shown.
- If no deductions were ever sent for a claim, a member who asks why they were paid less is
  told a person will check — never a reason Gooclaim OS made up.

### Document types

claim_form, discharge_summary, death_summary, final_bill, interim_bill, estimate_bill,
payment_receipt, prescription, investigation_report, lab_report, radiology_report,
medical_certificate, referral_letter, preauth_approval_letter, implant_invoice, fir_copy,
medico_legal_certificate, declaration_form, id_proof, address_proof, pan_card,
cancelled_cheque, policy_copy, death_certificate.

Case and separators do not matter. Any other name is kept as your own document type.

## Server identity

Before anything is read from — or written to — your SFTP server, your administrator checks
its fingerprint in Portal (in the `SHA256:…` form `ssh-keygen -lf` shows) and approves it.
If the server's key ever changes, Gooclaim OS stops until the new identity is approved.

Gooclaim OS can sign in to your server with an SSH key (Ed25519, ECDSA or RSA, with or
without a passphrase) or a password.
