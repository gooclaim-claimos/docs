---
title: "Your claims API"
description: "What Gooclaim OS asks your claims system for, the four ways it can sign in, and what the answer must contain."
---

When a member asks about a claim, Gooclaim OS asks your claims system's API for that one
claim.

## The request

```http
GET {your base address}/claims/{claim number}
```

- The claim number is one path segment, URL-encoded: a `/` or `?` in it cannot change the
  request.
- Your base address must be `https://`. An `http://` address is refused. Certificates are
  checked as normal.
- Redirects are not followed.

## Signing in

You choose how Gooclaim OS signs in when you add the connector in Portal. Credentials are
stored encrypted and are never shown again after you save them.

| Method | What you give | What Gooclaim OS sends |
|--------|---------------|------------------------|
| **API key** | The key, and optionally a header name | The key in `X-API-Key`, or in the header you name. Naming `Authorization` sends `Bearer {key}`. |
| **Basic** | A username and password | `Authorization: Basic …` (RFC 7617) |
| **OAuth 2.0 client credentials** | Client ID, client secret, token URL, optional scopes | First asks your token URL for a token (client ID and secret sent as HTTP Basic, as RFC 6749 requires every token endpoint to accept), then sends `Authorization: Bearer {token}`. |
| **Mutual TLS** | A client certificate and private key (PEM), and optionally your own CA certificate | The certificate during the TLS handshake. With a CA certificate given, only that CA is trusted for your server. |

- **OAuth tokens** are reused until shortly before they expire, then a new one is requested.
  If your API answers `401`, the token is dropped and the next call asks for a new one. The
  token URL must also be `https://`.
- **A changed secret** takes effect on the next call; a token obtained with the old secret is
  never reused.
- If the credentials are incomplete or the token URL gives no token, the call fails without
  contacting your claims API, and the failure names the field, never its value.

## The answer

| Your API answers | Gooclaim OS treats it as |
|------------------|--------------------------|
| `200` with a JSON object | The claim |
| `404` | No such claim — the member is told it was not found |
| Anything else, or no answer within 10 seconds | Your system is unavailable |

## When your system is unavailable

- There is no immediate retry. If you also share a claims file over SFTP, Gooclaim OS reads
  the claim from there instead.
- After 5 failures in a row, Gooclaim OS pauses calls to your API for 60 seconds, then tries
  again.
- A claim it has just read is kept for 5 minutes, so repeated questions do not call your
  API each time. A "not found" is never kept.

## What the answer must contain

Your JSON can use your own field names and nesting; the field mapping translates them. What
Gooclaim OS needs to find in it:

| Field | Required | Notes |
|-------|----------|-------|
| Claim number | Yes | |
| Status | Yes | Mapped to one of: APPROVED, REJECTED, PENDING, UNDER_REVIEW, NOT_FOUND |
| Claim type | No | CASHLESS_PREAUTH, CASHLESS_DISCHARGE or REIMBURSEMENT |
| Policy number, hospital | No | |
| Amounts claimed and approved | No | In rupees (commas allowed) or paise |
| Admission and discharge dates | No | |
| Submitted, received, decided and last-updated times | No | |
| Rejection reason and query reason | No | A code and/or text |
| Amount paid, date paid, payment reference | No | The reference is the UTR or cheque number. No date paid means not paid. |
| Pre-authorisation reference, approved amount, valid-until date | No | |
| Documents | No | A list; each with a document type and a state: REQUIRED, RECEIVED, VERIFIED or REJECTED |
| Deductions | No | A list; each with your reason code, and optionally your wording and the amount. Your wording is shown to the member as you wrote it. |

- Amounts are read in rupees (commas allowed) or paise, as set in the mapping.
- Dates are read as `DD/MM/YYYY` or `YYYY-MM-DD` by default; other formats can be set in the
  mapping.
- Times are read as ISO 8601. A time without a timezone is taken in your timezone (India
  time unless set otherwise).
- Document types are matched to Gooclaim's catalogue (see
  [document types](/integration/files#document-types)); any other name is kept as your own.
- A value the mapping does not know is never guessed: the claim is not used, and the stop is
  recorded for the Gooclaim team to fix the mapping.
- **No deductions list is not the same as an empty one.** If your answer carries no
  deductions, a member who asks why they were paid less is told a person will check. An
  empty list means nothing was deducted.

## A claims file instead of an API

If your claims sit in a file on your SFTP server rather than behind an API, Gooclaim OS can
read the claim from that file (CSV, UTF-8, with a header row), matching the claim number
exactly. The mapping then needs the claim number, status, submitted time and last-updated
time.
